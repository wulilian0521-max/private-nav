# 私人导航 · 开源整理演示版

这份文件夹演示如何从私人网站项目中，单独整理一份可继续准备开源的代码副本。当前为开源准备阶段，代码存放在私有 GitHub 仓库中，尚未向公众开放。

## 这次实际做了什么

1. 从原项目复制网页、Python 后端、网站信息识别、AI 命名与搜索模块，以及通用 Docker 配置。
2. 保留空白的 `.env.example`，AI 接口地址、模型和密钥由使用者自己填写。
3. 扩充 `.gitignore`，排除数据库、真实环境配置、日志和备份。
4. 没有复制原有的个人部署说明、systemd 服务文件、本机启动和 iPhone 连接脚本。这些需要另行整理，避免沿用个人环境。
5. 没有复制数据库、设备授权、配对码、真实密钥、私人网址列表或运行日志。原项目和线上网站不受此次复制影响。

本副本按明确文件清单复制，不包含 Git 历史，也不包含原聊天记录。

## 主要文件

- `web/`：网页布局、样式、图标和交互。
- `app.py`：网址存储、设备配对和后端接口。
- `site_ai.py`、`site_search.py`、`site_metadata.py`：AI 与网站信息功能。
- `.env.example`：供使用者填写的配置样例。
- `Dockerfile`、`compose.yaml`、`Caddyfile`：通用服务器部署配置。
- `compose.existing-proxy.yaml`：已有反向代理环境的另一种配置。

## 别人将如何使用

使用者拿到代码后，在自己的服务器配置域名，把 `.env.example` 复制为 `.env`，填写自己的配置，启动服务，再使用新生成的配对码授权自己的浏览器。网址和授权由各自的实例保存。

完整功能需要 Python 后端与数据库，不能只上传 HTML 到 GitHub Pages。AI 配置留空时仍可使用非 AI 功能。

## 距离正式开源还需要什么

- 确认愿意采用的许可证，并添加 LICENSE。
- 核对图标等素材的来源与再分发权利。
- 补齐安装步骤和使用演示数据的截图。
- 在全新环境验证首次启动、配对和部署。此次没有构建 Docker 镜像或运行服务，不能把这份副本视为已通过完整部署验收。
- 上传前再次检查最终文件列表。

整理后的代码已上传到私有 GitHub 仓库，未公开访问，也未更改原项目或线上服务。
